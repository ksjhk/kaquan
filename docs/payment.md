# 支付（商户号）配置教程

部署方自己的收款能力：**买家充值/付款的钱，100% 进入你在这里配置的微信/支付宝商户号**。
本系统没有任何内置或默认收款账户——不配置，收款功能就是关闭状态（充值接口会明确报错提示配置），不存在"钱付给别人"的情况。

## 一、先搞懂钱怎么流

一套部署里有三层账，互相独立：

1. **买家 → 你**：买家在你的平台上充值，扫微信/支付宝二维码付款，钱进**你自己的商户号**（本文配置的这批参数）。
2. **买家 ↔ 你的平台**：买家调 API 下单，扣的是**他在你平台上的余额**（数字账，现金你在第 1 层已经收到）。
3. **你 → 卡世界开放平台**：你的系统调供货接口发货，按成本价扣**你在 kashijie.com 的供货余额**（`.env` 里的 `SUPPLIER_*` 密钥对应账户）。这一层是你的进货成本。

零售价减成本价，就是你的利润。第 1 层收不到钱只可能是没配置商户号——按下面配好即可。

## 二、微信支付（Native 扫码）

需要：一个已认证的微信商户号（个体户/企业均可申请，pay.weixin.qq.com）。

| .env 项 | 从哪里拿 |
|---|---|
| `OPEN_WX_APPID` | 微信公众平台（mp.weixin.qq.com）公众号的 AppID，并在商户平台「产品中心 → AppID 账号管理」绑定该 AppID |
| `OPEN_WX_MCH_ID` | 微信商户平台首页的商户号（10 位数字） |
| `OPEN_WX_API_KEY` | 商户平台「账户中心 → API 安全 → APIv2 密钥」自行设置的 32 位密钥 |
| `OPEN_WX_CERT_PATH` / `OPEN_WX_KEY_PATH` | 仅退款需要。商户平台「API 安全 → API 证书」下载 `apiclient_cert.pem` / `apiclient_key.pem`，填绝对路径。不配置退款则留空 |

另外两件事：

- **开通 Native 支付**：商户平台「产品中心 → Native 支付」开通（充值二维码走这个）。
- **回调地址**：`https://你的域名/api/open/platform/recharge/notify`。V2 Native 下单时由接口动态上送，无需在商户平台固定配置；但要保证该地址公网可达。回调只做 ACK，到账以主动查单为准（`open:recharge-scan` 每分钟兜底），回调收不到也不影响入账。

## 三、支付宝（当面付 / 网站支付）

需要：支付宝开放平台（open.alipay.com）创建「网页&移动应用」。

| .env 项 | 从哪里拿 |
|---|---|
| `ALIPAY_APP_ID` | 应用详情页的 APPID |
| `ALIPAY_PRIVATE_KEY` | 「接口加签方式（密钥/证书）→ 密钥」里的**应用私钥**，转成单行填入 |
| `ALIPAY_PUBLIC_KEY` | 同页面的**支付宝公钥**（注意不是应用公钥），单行填入 |
| `ALIPAY_GATEWAY` | 保持默认 `https://openapi.alipay.com/gateway.do` |

签约能力（至少签一个，两个都签更稳）：

- **当面付**（推荐）：预下单直接出二维码，体验最好。
- **电脑网站支付 / 手机网站支付**：未签当面付时的兜底，返回跳转链接。
- **回调地址**：同上 `/api/open/platform/recharge/notify`，可在应用详情「应用网关/授权回调」之外的「接口内容加密/回调」处留空——下单时动态上送。

## 四、自检

配置完后在控制台发一笔 1 元充值：

- 出二维码/跳转链接 → 配置正确。
- 提示「微信支付未配置：请在 .env 填写 …」→ 对应项为空或没生效（改完 `.env` 记得 `php artisan config:clear`）。
- 扫码付款后余额未到账 → 检查回调地址公网可达性，并确认 `open:recharge-scan` 定时任务已配置（它每分钟主动查单兜底）。
